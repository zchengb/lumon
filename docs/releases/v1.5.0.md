# Lumon v1.5.0

## Dashboard and Workflow execution

- Add an Overview map of Workspace repositories, workflows, capabilities and
  configured services, with links to the corresponding Dashboard sections.
- Run a saved, enabled Workflow manually without enabling its schedule. Manual
  and scheduled executions share an exclusive lock to prevent overlapping runs.
  Unsaved Workflow edits must be saved before execution.
- Simplify delivery history and scheduler activity tables while retaining their
  detailed execution records. Refine localized titles, notices and schedule UI.
- Show deduplicated Auto Scan findings with status filters and expandable evidence.
  Ignore choices are stored locally without rewriting scan receipts or changing
  external Jira issues.

## Visual assistance

- Show passive iOS Simulator, Android Emulator, browser and Docker prerequisite
  checks on Overview, with refresh, timestamps and contextual help.
- Expose the same report through `lumon doctor --visual --json` and Agent context.
  Normal conversation prompt preparation runs off the event loop; steering uses
  the cached snapshot so urgent follow-up instructions do not wait for probes.
- Define the Auto Delivery Debug/dev visual loop and final screenshot evidence
  rules. Project startup, authorized login and Jira attachments remain governed
  by Workspace capabilities and instructions.

## Upgrade and boundaries

Run `lumon update` after publication and restart idle Dashboard and Agent services
to load the new code. Existing Workspace configuration, credentials, schedules
and automation enablement are preserved.

Tool readiness is not proof that an application builds, logs in or passes visual
checks. This release does not install SDKs, boot devices, package a production
emulator runner or provision a new Mac. Screenshot/Jira guidance is not a new
automatic evidence uploader. No real Workflow needs to be executed to upgrade.
