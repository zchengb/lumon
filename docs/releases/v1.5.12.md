# Lumon 1.5.12

- Ask the Auto Scan Agent to compare candidate findings and historical issues by root cause, trigger and affected code paths, including ignored and resolved issues.
- Persist evidence-backed semantic associations so differently worded duplicates share one identity in issue history. Preserve manual ignore choices across equivalent records.
- Require fresh configured-branch rechecks for all known issues, including those outside the discovery lookback. Project verified fixes and recurrences into history without rewriting original receipts or reports.
- Reject invalid associations and conflicting resolution evidence. Missing or unverified rechecks make a scan incomplete; incomplete scans do not run completion hooks.
- Exclude confirmed duplicate candidates from new finding counts, reports, scan notification findings and completion hooks.
- Add semantic matching, ignore inheritance, persistence and incomplete-review regression coverage, and update Dashboard documentation.

Existing Workspace configuration, schedules, receipts, reports and worktrees are preserved. This release does not rerun scans or retroactively change existing Jira records and notifications. Historical duplicates merge only after an Agent provides a validated semantic association in a subsequent scan. Evidence validation checks structure and consistency; actual Agent reasoning remains subject to review, and static code review does not establish runtime verification.
