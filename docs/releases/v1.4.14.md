# Lumon v1.4.14

## Codex recovery

- Preserve successful results after a recoverable Codex stream error when the
  turn subsequently completes and the CLI exits successfully.
- Save and send the final Agent reply to Feishu instead of discarding it and
  reporting a generic execution failure after a successful reconnection.
- Apply the fix in the shared Codex execution tool used by chat, Auto Scan and
  Auto Delivery. Do not rerun requests or change their model or timeout settings.
- Keep explicit terminal failures, unresolved stream errors, nonzero exits and
  real timeouts as failures; never send a partial answer as a successful result.
- Add regression coverage for recovery, terminal failures, timeouts, credential
  redaction, final reply persistence and duplicate-message delivery.

## Upgrade

After publication, run `lumon update`. Restart the Agent after its current
conversations finish and restart the Dashboard to load the new code. Existing
scheduled jobs load the updated package on their next invocation; do not reload
their LaunchAgents or interrupt active polls.

Workspace data, credentials, model preferences and schedules remain unchanged.
This release fixes result handling, not model or database latency, and does not
automatically resend historical failed replies.
